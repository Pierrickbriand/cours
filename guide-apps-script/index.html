Avant de commencer

Comment parler à Claude

Claude écrit le code. Vous le collez, vous le testez, vous lui rapportez ce qui se passe. Cinq règles :

  • collez toujours le code complet, jamais un extrait, et dites ce que vous attendez ;
  • demandez des fichiers complets, prêts à coller ;
  • ne demandez qu’un changement à la fois ;
  • en cas d’erreur, collez le message exact, sans le résumer ;
  • avant de coller un code incompris, demandez : « explique-moi en trois phrases ce que fait ce code ».

Étape 0 sur 9

Comprendre le schéma avant de toucher à quoi que ce soit

But de l’étape. Comprendre les trois pièces de votre application avant d’ouvrir le moindre outil.

Pour comprendre

Une page HTML ouverte dans le navigateur ne peut pas écrire dans votre Drive. Il lui faut un intermédiaire.

Cet intermédiaire s’appelle Google Apps Script. C’est l’outil de Google pour écrire de petits programmes reliés à Drive, à Sheets ou à Gmail. Votre page lui demande, il lit ou écrit dans la feuille, puis il répond.

Les gestes

  1. relisez le schéma des trois pièces, en haut de la page ;
  2. dites avec vos mots ce que fait chaque pièce : l’interface, le serveur, les données ;
  3. ouvrez votre compte Google personnel (Gmail), de préférence dans une fenêtre de navigation privée ;
  4. retrouvez le code complet de votre page HTML finale ;
  5. ouvrez une conversation Claude réservée à ce travail et collez-y le code de votre page.

Compte d’école ou compte personnel ?

Certains établissements bloquent la publication d’applications web depuis un compte scolaire. Le compte personnel est le plus sûr. Si votre compte d’école refuse l’étape 5, ne cherchez pas à contourner le blocage : recommencez avec votre compte personnel.

Étape 1 sur 9

Créer la base de données (la feuille Google Sheets)

But de l’étape. Créer la feuille qui stockera toutes les données de votre application.

Pour comprendre

Une feuille Google Sheets se compose d’onglets (les languettes en bas de l’écran). Chaque onglet joue le rôle d’une table : un onglet par type d’information.

Les gestes

  1. ouvrez Google Drive, cliquez sur « Nouveau », puis sur « Google Sheets » ;
  2. nommez la feuille en cliquant sur son titre, en haut à gauche, par exemple « CRM – données » ;
  3. collez dans Claude le code de votre page et la consigne ci-dessous, pour obtenir les onglets et les colonnes ;
  4. créez un onglet par type d’information (Clients, Contacts, Échanges…) avec le « + » en bas à gauche ;
  5. écrivez en ligne 1 le nom des colonnes, sans accent ni espace si possible (id, nom, email, statut, date) ;
  6. gardez « id » comme première colonne : un identifiant unique par ligne, qui servira à modifier ou à supprimer une ligne.

Vous avez renommé un onglet après avoir reçu le code

Étape 2 sur 9

Ouvrir Apps Script depuis la feuille

But de l’étape. Ouvrir l’éditeur de code de Google, rattaché à votre feuille.

Pour comprendre

Ouvert depuis la feuille, le script y est rattaché. Il peut donc la lire sans que vous ayez un identifiant à copier.

Une fonction est un petit bloc de code qui porte un nom et fait une tâche. Celle que vous allez voir est vide.

Les gestes

  1. dans votre feuille, ouvrez le menu « Extensions » ;
  2. cliquez sur « Apps Script » : un nouvel onglet s’ouvre ;
  3. en haut à gauche, cliquez sur « Projet sans titre » et renommez le projet, par exemple « CRM – application » ;
  4. dans la liste « Fichiers », à gauche, repérez « Code.gs » : il contient déjà une fonction vide.

Pour comprendre

google.script.run est le pont par lequel votre page appelle les fonctions du serveur.

Étape 4 sur 9

Premier test dans l’éditeur et autorisations

But de l’étape. Lancer une fonction une première fois et autoriser votre script à lire votre feuille.

Pour comprendre

Une autorisation est la permission que vous donnez à votre propre script d’accéder à votre feuille. Google la demande une seule fois.

Les gestes

  1. dans le menu déroulant au-dessus du code, choisissez une fonction de lecture, par exemple celle qui renvoie les lignes ;
  2. cliquez sur « Exécuter » ;
  3. première fois seulement : cliquez sur « Examiner les autorisations », puis choisissez votre compte ;
  4. sur l’écran « Google n’a pas validé cette application », cliquez sur « Paramètres avancés » ;
  5. cliquez sur « Accéder à [nom du projet] (non sécurisé) » ;
  6. cliquez sur « Autoriser » (selon la version de l’écran : cochez « Tout sélectionner », puis cliquez sur « Continuer ») ;
  7. lisez le « Journal d’exécution », en bas de l’éditeur : il doit afficher « Exécution terminée », sans message rouge.

Cet écran est normal

L’écran « Google n’a pas validé cette application » est normal : le développeur, c’est vous. C’est ici que beaucoup d’étudiants s’arrêtent : continuez. Ne contournez jamais cet écran pour un script reçu d’une personne inconnue.

Étape 5 sur 9

Publier l’application web

But de l’étape. Mettre votre application en ligne, à une adresse que vous seul pouvez ouvrir.

Pour comprendre

Un déploiement est la mise en ligne d’une version de votre code, à une adresse web. Vous en créez un.

« Moi uniquement » signifie que vous seul pouvez ouvrir l’application, connecté à votre compte Google.

Les gestes

  1. en haut à droite de l’éditeur, cliquez sur « Déployer », puis sur « Nouveau déploiement » ;
  2. à côté de « Sélectionner le type », cliquez sur la roue dentée, puis sur « Application Web » ;
  3. dans « Description », écrivez « Version 1 » ;
  4. pour « Exécuter en tant que », choisissez « Moi » ;
  5. pour « Qui a accès », choisissez « Moi uniquement » pour commencer ;
  6. cliquez sur « Déployer » ; si Google demande une autorisation, acceptez-la comme à l’étape 4 ;
  7. copiez l’adresse qui se termine par /exec ;
  8. ouvrez cette adresse dans un nouvel onglet.

Étape 6 sur 9

Tester la lecture, puis l’écriture

But de l’étape. Vérifier que votre application lit votre feuille, puis qu’elle y écrit.

Pour comprendre

L’ordre compte : la lecture d’abord, l’écriture ensuite. Si la lecture ne marche pas, l’écriture ne marchera pas non plus.

N’utilisez que des données fictives : jamais de vraies données de clients pendant ce travail.

Les gestes

  1. ajoutez à la main une ligne dans un onglet de la feuille, sous les noms de colonnes ;
  2. rechargez l’application : la ligne apparaît ;
  3. ajoutez une fiche depuis l’application : une nouvelle ligne apparaît dans la feuille ;
  4. modifiez cette fiche depuis l’application : la ligne change dans la feuille ;
  5. supprimez cette fiche depuis l’application : la ligne disparaît de la feuille.

Étape 7 sur 9

La boucle d’itération

But de l’étape. Apprendre le cycle que vous referez dix fois : changer, publier, vérifier.

Pour comprendre

Une version est une photo de votre code à un instant donné. L’adresse /exec affiche la version que vous avez publiée, pas votre dernier enregistrement.

Le cache est la copie de la page que votre navigateur garde en mémoire. Il peut vous afficher l’ancienne page.

Les six temps du cycle

  1. 1Un changementdécrivez à Claude un seul changement à la fois (« ajoute un champ téléphone », « ajoute un filtre par statut ») ;
  2. 2Fichiers completsdemandez les fichiers complets mis à jour ;
  3. 3Coller et enregistrercollez-les dans Code.gs et dans index.html, puis enregistrez ;
  4. 4Feuille à joursi la structure de la feuille change (nouvelle colonne), modifiez-la à la main avant de tester ;
  5. 5Nouvelle versionpubliez une nouvelle version : « Déployer », « Gérer les déploiements », icône crayon, « Version » : « Nouvelle version », puis « Déployer » ;
  6. 6Rechargerrechargez l’adresse de votre application avec Ctrl+Maj+R (Cmd+Maj+R sur Mac) pour vider le cache.

↺ Puis on recommence au temps 1 : chaque changement suit ce même cycle.

Enregistrer ne suffit pas. Sans « Nouvelle version », l’adresse /exec continue d’afficher l’ancien code. C’est l’erreur la plus fréquente.

Astuce pour aller vite

Cliquez sur « Déployer », puis sur « Tester les déploiements ». Vous obtenez une adresse qui se termine par /dev. Elle affiche toujours le dernier code enregistré, sans nouvelle version. Elle ne s’ouvre que pour les personnes qui peuvent modifier le script : vous. Utilisez-la pour tester, puis remplacez-la par l’adresse /exec pour partager.

Étape 9 sur 9

Bonnes pratiques avant de partager

But de l’étape. Protéger votre travail et vos données avant de montrer l’application à quelqu’un.

Pour comprendre

Votre application s’exécute sous votre identité (« Moi »). Si vous l’ouvrez à d’autres personnes, elles agissent sur votre feuille à travers elle. Réfléchissez donc à qui vous donnez l’adresse.

Le RGPD est le règlement européen qui protège les données personnelles. Des données fictives vous mettent à l’abri.

Les gestes

  1. faites une copie avant toute grosse modification : dans la feuille, « Fichier », puis « Créer une copie ». Le script rattaché est copié, sans son déploiement ;
  2. consultez l’historique de la feuille : « Fichier », puis « Historique des versions » ;
  3. ne saisissez jamais de vraies données de clients pendant ce travail : des données fictives suffisent ;
  4. ne donnez l’adresse qu’à des personnes précises ; n’ouvrez « Qui a accès » à toute personne ayant un compte Google que si c’est voulu ;
  5. demandez à Claude une relecture de sécurité, avec la consigne ci-dessous.
